# Kira OS — сводный список «что ещё добавить» (2026-11-09)

Собрано из решений владельца (память проекта), HANDOFF, RELEASE_GAPS и UNIFIED_RELEASE_PLAN. Порядок — по плану владельца.
Статус сборки остаётся PREVIEW, пока открыт релизный гейт (RELEASE_GAPS, раздел 8).

## 0. Решение 2026-11-09: компилятор KCC входит в обновление как есть
Гонка за скоростью clang -O2 (среднее отставание ~13%, худший случай ~70%) НЕ блокирует выпуск. Скорость — отдельные патчи позже.

## 1. Компилятор (после выпуска, отдельными патчами)
- Скорость: аллокатор регистров с разбиением интервалов, режим всей программы, развёртка циклов, векторизация SSE2/AVX2 по набору команд машины.
- Язык: `long double`, `_Complex`, `_Thread_local`, computed goto; структуры с float по значению по SysV ABI.
- Инструменты: `kcc -c` для AArch64, ассемблер для .s-файлов ядра (сейчас nasm), компоновка нескольких объектов (klink, настоящая GOT).

## 2. Безопасность памяти (первый приоритет владельца после компилятора)
- Сделано (патч 1-2): ранний boot.s с NX выше образа. Осталось: ранние 2-МБ страницы самого образа RWX до vmm_enforce_wx; нет KASLR; страница AP-трамплина.
- Откат всего диска откатывает и защиту от отката: нужен TPM/RPMB/счётчик прошивки; второй ключ подписи не заведён.
- Приложения проверяются только SHA-256. (USB только для чтения по умолчанию - сделано, запись: `remount usbN rw`.)
- Сделано (патч 1-2): двойное освобождение стека потока, ловушка NULL на AArch64. Векторы MSI: утечки нет (слоты переиспользуются).

## 3. Драйверы, DMA, платформа
- Драйвер RTL8139 «с чистого листа» по публичной спецификации (issue #8).
- IOMMU: VT-d сейчас изолирует только virtio-blk; нет перенаправления прерываний, нет ARM SMMU (issue #10).
- Подписи драйверов: каталог, ротация и отзыв ключей, drvget/mind_build с защитой от отката времени (issue #9).
- ACPI: AML, _PRT (INTx), IVRS; проверка некогерентного DMA на ARM.
- Драйверы в user space; приложение установки драйверов; слой совместимости: загрузка BSD-исходников и сборка на устройстве.

## 4. Загрузка и сборка образа
- Доказать, что в итоговом ISO нет GRUB; UEFI на ARM64 ни разу не запускался.
- Образ: убрать лишние тестовые программы из пользовательского образа, показывать список /bin в Explorer.

## 5. Разум (Mind) и ИИ
- ≥ +18 рычагов с большей самостоятельностью, обучение на GitHub; per-core порог перегрузки, плавная стабилизация.
- Шесть разделов панели («Состояние», «Прогнозы», «Обучение», «Решения», «Процессы», «Оборудование») только через опубликованный API; Mind не управляет окнами.
- Задания на сборку: проверить `build allow ИМЯ sig` в QEMU, разрешения после перезагрузки, квота времени сборки, потребитель результата зонда.
- Устранить лаги Разума и WASM (одно ядро, медленный образ).

## 6. Интерфейс (ждёт образцы владельца)
- Единый стиль по присланным референсам (тёмно-синий фон, неоновые акценты, верхняя панель, боковая панель иконок).
- Проводник в стиле mc (две панели), полноэкранный режим и сворачивание, кириллица, масштабирование, низкая память.

## 7. Большие направления
- Цех с боксами (параллельная сборка); язык инструкций для ИИ и человека + приложение.
- x86 и ARM64 в паритете; изоляция приложений в духе Qubes/seL4 (приложения в ВМ).
- Исследование выбора технологий: research/kira-architecture-selection-2026-11/ — по его итогам владелец решает, что переделывать.
