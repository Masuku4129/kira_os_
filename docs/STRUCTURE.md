# Структура KIRA OS

Восемь уровней отвечают за ответственность и направление зависимостей, а не за каталоги. Файлы остаются там, где их ждут сборочные скрипты;
принадлежность файла уровню задаёт `docs/architecture/levels.map`, а `ci/check_layers.py` в CI проверяет:
каждый исходник отнесён к уровню, новых зависимостей «вниз → вверх» нет. Старые нарушения перечислены в `docs/architecture/layer_violations.baseline`
и устраняются по одному (проверка требует вычеркнуть устранённое, поэтому список может только уменьшаться).

| Ур. | Название | Что входит |
|---|---|---|
| 1 | Платформа | описание железа: ACPI, FDT, hwprofile, mbinfo, platform |
| 2 | HAL, устройства, драйверы | `arch/`, PCI/MSI/IOMMU, USB, virtio, диски, сеть, звук, ввод, фреймбуфер, `kdrv.c` |
| 3 | Ядро | процессы, потоки, планировщик, память, syscalls, futex, ELF, примитивы безопасности (caps, trust, W^X, crypto) |
| 4 | Безопасность (политика) | подписи и состояние KDRV, trust-ключи, иммунная проверка |
| 5 | Mind | `mind*`, devhealth, experience, life, scale, watchdog |
| 6 | Системные службы | KiraFS/VFS/FAT, сеть, графсервер, консоль, сборка (`buildcmd`) |
| 7 | Среды выполнения | WASM (KVR), libc-минимум, слой BSD для драйверов, KCC-рантайм |
| 8 | Пользовательское окружение | рабочий стол, окна, проводник, док, программы `userland/` |
| 0 | Сквозное | загрузка и BootInfo, KCC/KAS/KLink, tools, ci, tests |

`attic/` — код, который написан, но не подключён к сборке (ACPI `_PRT` ×3 варианта, IOMMU-модули AMD-Vi/SMMU/VT-d-discovery, kdrv_manager,
boot_handoff, fdt_boot). Он не удалён, потому что относится к плану (DMA/IOMMU, маршрутизация прерываний), но и не считается частью системы.
Модуль возвращается из `attic/` в дерево только вместе с подключением к сборке и тестом.

Форматы файлов и языки: `docs/architecture/FORMATS_AND_LANGUAGES.md`. Чего ещё нет: `docs/BACKLOG.md`, `docs/RELEASE_GAPS.md`.
