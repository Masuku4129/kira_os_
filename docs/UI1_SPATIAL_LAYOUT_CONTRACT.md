# KIRA OS — UI-1 contract: Spatial Minimal layout и design tokens

**Статус:** технический контракт для следующего GUI implementation slice; не означает, что layout уже реализован.  
**Связь:** мастер-план J/J.1, D (KIRA Mind), K (System API), N (quality); `docs/KIRA_DESIGN_SYSTEM.md`, `docs/UI0_SPATIAL_MINIMAL_AUDIT.md`.

## 1. Цель и границы

Преобразовать существующую оболочку в спокойное пространственное рабочее окружение, сохранив compositor, оконную модель, запуск приложений, системные API и производительность damage-based rendering.

В UI-1 не менять production GUI. Зафиксировать состояния, визуальные токены, правила адаптации и проверяемые инварианты. UI-2 будет отдельным вертикальным срезом за переключателем layout mode.

## 2. Модель рабочего пространства

### Постоянный слой (idle)

1. **Навигационный rail:** компактный вход в Домой, Приложения, Файлы и Систему. Не содержит список всех запущенных окон. Может сворачиваться в одну точку вызова на узких экранах.
2. **Dock:** ограниченный набор пользовательских закреплений и краткий статус активного приложения. Не содержит все открытые окна и не растёт без ограничений.
3. **System zone:** только время и необходимые индикаторы подключения/звука/питания. Подробная телеметрия не отображается.
4. **Workspace switcher:** компактный переключатель только если есть более одного пространства.
5. **KIRA AI entry:** одна точка вызова; большая панель скрыта в idle.
6. **Canvas:** центральная свободная область; фон не содержит обязательных анимированных элементов.

### Контекстные состояния

| Состояние | Открывается | Обязательное поведение |
|---|---|---|
| App discovery | Кнопка приложений / системный поиск | Поиск и категории; закрывается без потери текущего контекста |
| KIRA AI | Выделенный вызов / горячая клавиша | Панель появляется по запросу, не захватывает фокус без явного действия |
| Quick system | Нажатие system zone | Сеть, звук, питание; без постоянных графиков |
| Diagnostics | Из System / Mind | CPU, RAM, диск, службы и объяснения только здесь |
| Notifications | Значок/системное событие | Группировка, приоритет, отсутствие кражи фокуса |
| Window overview | Жест/клавиша/команда | Временный обзор окон; не превращается в постоянный список |

### Оконная модель

- Окна принадлежат текущему пространству и задаче; WM продолжает отвечать за z-order, focus, resize и fullscreen.
- Заголовки/рамки не обязаны повторять привычный «светофор» как постоянную доминирующую деталь; конкретная форма — отдельная проверка UI-2.
- Запущенные приложения доступны через временный overview и Dock, если закреплены; список окон не смешивается с навигацией.
- API `wm_create*`, visibility, input и frame invalidation сохраняются на первом переходном этапе.

## 3. Responsive layout contract

Размеры ниже — стартовые токены в логических пикселях, не жёсткие физические координаты. Итоговые значения калибруются на 1024×768, 1280×720, 1920×1080 и узком touch viewport.

| Token | Начальное значение | Правило |
|---|---:|---|
| `space-1` | 4 | Микроотступ |
| `space-2` | 8 | Внутренний отступ компактных элементов |
| `space-3` | 12 | Межэлементный интервал |
| `space-4` | 16 | Базовый отступ поверхности |
| `space-6` | 24 | Разделение смысловых групп |
| `radius-control` | 12 | Кнопки и интерактивные элементы |
| `radius-surface` | 20 | Основные поверхности |
| `rail-expanded` | 64 | Компактная навигация |
| `rail-collapsed` | 44 | Узкий режим |
| `dock-height` | 64 | Компактный Dock |
| `target-min` | 40 | Минимальная touch-цель |

Правила:
- Геометрия задаётся от safe-area и DPI scale, не от фиксированного 1920×1080.
- При недостатке ширины rail сворачивается; подписи переходят в доступные подсказки/семантические имена, а не исчезают из accessibility tree.
- Dock уменьшает количество одновременно видимых элементов и использует overflow, а не сжимает цели нажатия ниже минимума.
- Окна ограничиваются доступной областью и не перекрывают системную зону без причины.
- Для 4:3/узкого экрана не создавать постоянную правую AI-панель.

## 4. Семантические design tokens

### Цвета

| Token | Значение | Назначение |
|---|---|---|
| `surface-canvas` | `#070D19` | Базовая подложка |
| `surface-raised` | `#0C1629` | Окна и всплывающие поверхности |
| `surface-control` | `#13213A` | Интерактивные элементы |
| `border-subtle` | `#263653` | Тонкие разделители |
| `accent-primary` | `#9B6BFF` | Фирменный фиолетовый |
| `accent-secondary` | `#42A5FF` | Вторичный синий |
| `text-primary` | `#F1F3FA` | Основной текст |
| `text-secondary` | `#AAB5CC` | Вторичный текст |
| `state-success` | `#35C995` | Успех |
| `state-warning` | `#F2B84B` | Предупреждение |
| `state-danger` | `#F07178` | Ошибка |

Текущие `theme.h` значения не заменять вслепую: сначала сопоставить каждый используемый цвет семантическому token и проверить все системные приложения. Прозрачность — enhancement, а не основа контраста.

### Типографика

- Основной интерфейс: читаемый кириллический sans-serif; шрифтовые размеры выражаются токенами `type-caption`, `type-body`, `type-title`, `type-display`.
- Не использовать капслок для длинных подписей и не полагаться на пиктограмму без доступного названия.
- Минимальный размер основного текста должен оставаться читаемым после DPI scaling; точные px значения определить после проверки имеющегося font rasterizer и реального шрифта.

### Motion

- Анимации только функциональные: появление/скрытие поверхности, смена пространства, подтверждение действия.
- Никакого бесконечного свечения, пульсации или постоянно движущегося фона.
- Все переходы имеют reduced-motion вариант без движения; критические действия не зависят от завершения анимации.
- Длительности и кривые централизованы в tokens, не задаются локально каждой кнопкой.

## 5. Системные и security-инварианты

- Desktop chrome не получает привилегий; GUI действия идут через существующие проверяемые system APIs/capabilities.
- KIRA Mind может показывать объяснения/рекомендации, но не получает скрытых прав управления окнами/службами.
- Уведомление не крадёт ввод/фокус; опасные операции требуют явного подтверждения и аудита.
- Тексты/иконки из приложений считаются недоверенными данными; клиппинг и UTF-8 safety сохраняются.
- Контекстные поверхности не должны блокировать display thread ожиданием диска/сети/модели.

## 6. Acceptance tests для UI-2 и UI-5

1. **Idle cleanliness:** в Spatial Minimal idle отсутствуют список всех окон, открытый launcher, CPU/RAM/disk meters, постоянный AI widget и уведомления-история.
2. **Navigation reachability:** Домой, Приложения, Файлы, Система доступны мышью и клавиатурой; на touch targets не меньше `target-min`.
3. **Dock semantics:** закрепление сохраняется в `/var/dock`; активное незакреплённое приложение не добавляется в постоянный Dock.
4. **Window preservation:** create/show/hide/minimize/restore/raise/fullscreen/resize и Ring 3 input продолжают работать.
5. **Context surfaces:** launcher/AI/quick system/diagnostics открываются по действию и закрываются без потери окна/фокуса.
6. **Notifications:** обычное уведомление не крадёт фокус; критическое имеет понятный приоритет; история доступна отдельно.
7. **Contrast:** текст/иконки читаемы при выключенной прозрачности, без обоев и на светлом/тёмном фоне.
8. **Reduced motion:** все состояния доступны при motion disabled; функциональность не меняется.
9. **Responsive:** layout не обрезает элементы на 1024×768, 1280×720, 1920×1080 и узком viewport.
10. **Rendering:** damage redraw совпадает с full redraw; замер CPU/frame и pixels/frame не хуже legacy baseline сверх заранее согласованного budget.

## 7. Техническая стратегия миграции

- Добавить enum layout mode на уровне display/WM, default остаётся legacy до готовности нового режима.
- Отделить Dock model от side-panel projection: `dock_t` и файл `/var/dock` сохраняются.
- Развязать источники clock/meters от renderer: clock остаётся в system zone, meters публикуются в diagnostics model.
- Переназначить текущие tab actions на navigation destinations без изменения app open handlers.
- Временный window overview получает собственную поверхность/команду, не постоянный rail.
- Все изменения вводить по одному vertical slice и сопровождать regression tests.

## 8. Запреты на преждевременную реализацию

- Не удалять legacy layout до полного сравнения поведения.
- Не переписывать compositor, framebuffer, window manager или app ABI.
- Не добавлять второй Dock/task manager.
- Не добавлять постоянные виджеты CPU/RAM/Mind или большую AI панель.
- Не заявлять производительность, доступность или поддержку touch без фактических измерений/тестов.
