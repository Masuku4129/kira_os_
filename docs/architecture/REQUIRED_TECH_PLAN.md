# План обязательных технологий KIRA OS

Источник требований: список владельца проекта (языки, архитектура, форматы, инструменты, подсистемы).
Правило из `FORMATS_AND_LANGUAGES.md` действует и здесь: «РАБОТАЕТ» пишется только при наличии кода в сборке и теста.
Пункты, которые в исходном списке помечены «кандидат» или «требует оценки», остаются кандидатами до решения (ADR).

Статусы: **РАБОТАЕТ**, **ЗАЛОЖЕНО** (есть рабочая основа, нужна доработка), **РЕШЕНИЕ** (выбран вариант, кода нет),
**ОТЛОЖЕНО** (нужны предпосылки, перечислены), **КАНДИДАТ** (оценка не проведена).

## 1. Языки

| Пункт | Статус | Что есть / что дальше |
|---|---|---|
| C | РАБОТАЕТ | ядро, службы, программы (clang на сборке, KCC на устройстве) |
| Assembly | РАБОТАЕТ | NASM для ядра x86-64, `kcc/asm_*.c`; AArch64 — `arch/arm64` |
| Rust (no_std) | РАБОТАЕТ (основа) | `userland/rust/rsdemo.rs` + `build.sh`: no_std-программа собирается в ELF для Ring 3 и проверяется сценарием «isolation». Дальше: общий крейт-обёртка над системными вызовами |
| KCC | ЗАЛОЖЕНО | подмножество C, саморазмещение не закрыто (см. FORMATS_AND_LANGUAGES) |
| WASM | РАБОТАЕТ | `userland/wasm.c`, WASI-подмножество |
| Python, Bash | ОТЛОЖЕНО | нужен интерпретатор как WASM-модуль или нативный; для Bash — оболочка уровня 7 |
| SPARK Ada, Zig | КАНДИДАТ | Оценка: Zig даёт wasm32 и ELF без libc, но добавляет второй компилятор в CI; SPARK — для проверенных модулей (парсеры). Решение после стабилизации парсеров в C |

## 2. Архитектура

| Пункт | Статус | Что есть / что дальше |
|---|---|---|
| Capability-микроядро | ЗАЛОЖЕНО | `caps.c`, права процессов, изоляция Ring 3 (сценарий «isolation»). Ядро пока гибридное: драйверы KDRV вынесены в Ring 3, остальное в ядре |
| HAL | ЗАЛОЖЕНО | `arch/x86_64`, `arch/arm64`, `bootinfo_*` |
| IPC | ЗАЛОЖЕНО | `userland/ipc.c`; формат сообщений — CBOR (см. §3) |
| IOMMU / DMA | ЗАЛОЖЕНО | `iommu.c`, `iommu_vtd.c` (Intel VT-d); AMD-Vi и ARM SMMU не сделаны |
| WASM-рантайм | РАБОТАЕТ | см. §1 |
| KIRA IR / SSA | ЗАЛОЖЕНО | `kcc/ir.c`, `kcc/opt.c` — внутреннее представление KCC; отдельный стабильный формат IR не зафиксирован |
| MLIR | ОТЛОЖЕНО | нужен стабильный KIRA IR; сначала зафиксировать его формат |
| CAS / Merkle DAG | РАБОТАЕТ (библиотека) | `cas.c`: содержимое по SHA-256, дерево Меркла RFC 6962, пути включения, файлы кусками; тест `tests/cas_test.c`. Дальше: подключить к KiraFS |
| Copy-on-Write | ОТЛОЖЕНО | нужен слой блоков KiraFS с подсчётом ссылок; основа — CAS |
| LSM / B+Tree | ОТЛОЖЕНО | индекс каталогов KiraFS; сначала нагрузочные измерения |
| Async I/O | ОТЛОЖЕНО | очереди запросов в драйверах Ring 3; зависит от IPC без блокировки |
| Zero-copy | ОТЛОЖЕНО | общая память через capability; зависит от IOMMU и IPC |

## 3. Форматы

| Формат | Статус | Что есть / что дальше |
|---|---|---|
| ELF | РАБОТАЕТ | `elf.c` |
| UELF | РЕШЕНИЕ | не отдельный формат, а строгий профиль ELF64 для Ring 3 (EXEC, фиксированная база, сегменты ≤ 16), который уже принудительно проверяет `elf.c`; профиль описан здесь, второго загрузчика не заводим |
| WASM, WASI | РАБОТАЕТ | см. §1 |
| FDT/DTB | РАБОТАЕТ | `fdt.c` |
| ISO, IMG | РАБОТАЕТ | `tools/mkiso_own.sh`, образы диска |
| KiraFS | РАБОТАЕТ | `kfs.c` |
| CBOR | РАБОТАЕТ | `cbor.c` (RFC 8949): кодер/декодер, детерминированная форма, строгий режим, фаззинг; тест `tests/cbor_test.c`. Выбран как формат сообщений и манифестов |
| FlatBuffers, Cap'n Proto | РЕШЕНИЕ | не вводятся: CBOR закрывает задачу без кодогенерации. Пересмотр, если понадобится zero-copy доступ к большим структурам |
| Zstd | РАБОТАЕТ (декодер) | `zstd.c` (RFC 8878): 37 эталонных кадров уровней 1–19, контрольные суммы, многокадровость, потоковая выдача, отказ на битых и усечённых данных; тест `tests/zstd_test.c`. Кодера нет (на устройстве он не нужен для первых сценариев) |
| PEM/DER | ЗАЛОЖЕНО | DER-разбор — в `userland/x509.c` (цепочки TLS); PEM-обёртка как отдельный модуль не вынесена |
| YAML/JSON | ОТЛОЖЕНО | конфиги пока в простых текстовых форматах; JSON-разбор понадобится вместе с Python/Bash |
| Arrow, Parquet | ОТЛОЖЕНО | нужны только для аналитики Mind; зависят от Zstd (готов) и схем |

## 6. Очерёдность дальше

1. Подключить `cas.c` и `zstd.c` к KiraFS (сжатые и дедуплицированные блоки) — даёт COW и Merkle-проверку.
2. Зафиксировать формат KIRA IR (по `kcc/ir.c`), затем решать про MLIR.
3. Async I/O и zero-copy поверх IPC с CBOR-сообщениями.
4. Python/Bash как WASM-модули; к ним JSON.
5. AMD-Vi и ARM SMMU для IOMMU.
6. Оценка Zig и SPARK Ada (ADR).
