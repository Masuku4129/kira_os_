# План обязательных технологий KIRA OS

Источник требований: список владельца проекта (языки, архитектура, форматы, инструменты, подсистемы).
Правило из `FORMATS_AND_LANGUAGES.md` действует и здесь: «РАБОТАЕТ» пишется только при наличии кода в сборке и теста.
Пункты, которые в исходном списке помечены «кандидат» или «требует оценки», остаются кандидатами до решения (ADR).

Статусы: **РАБОТАЕТ**, **ЗАЛОЖЕНО** (есть рабочая основа, нужна доработка), **РЕШЕНИЕ** (выбран вариант, кода нет),
**ОТЛОЖЕНО** (нужны предпосылки, перечислены), **КАНДИДАТ** (оценка не проведена).

## 1. Языки

| Пункт | Статус | Что есть / что дальше |
|---|---|---|
| C | РАБОТАЕТ | ядро, службы, программы (clang на сборке, KCC на устройстве) |
| Assembly | РАБОТАЕТ | NASM для ядра x86-64, `kcc/asm_*.c`; AArch64 — `arch/arm64` |
| Rust (no_std) | РАБОТАЕТ | `userland/rust/lib/kira.rs` (системные вызовы, вход, паника, DMA/MMIO-обёртки; unsafe только там), драйвер Ring 3 `rsedu.rs` для устройства edu без unsafe в коде драйвера (сценарий `drv-edu`, включая выход за BAR = паника, код 101), программа `rsdemo.rs`. Сборка требует core для x86-64; на ARM-хосте шаг пропускается, ОС собирается без Rust |
| KCC | ЗАЛОЖЕНО | подмножество C; самосборка KCC и ядро, собранное только KCC+KAS+KLink, проверяются в CI (задание own-toolchain) |
| WASM | РАБОТАЕТ | `userland/wasm.c`, WASI-подмножество |
| Python, Bash | ОТЛОЖЕНО | нужен интерпретатор как WASM-модуль или нативный; для Bash — оболочка уровня 7 |
| SPARK Ada, Zig | РЕШЕНИЕ | не вводятся, обоснование и условия возврата — в `ADR-0001-ir-mlir-zig-spark.md` |

## 2. Архитектура

| Пункт | Статус | Что есть / что дальше |
|---|---|---|
| Capability-микроядро | ЗАЛОЖЕНО | `caps.c`, права процессов, изоляция Ring 3 (сценарий «isolation»). Ядро пока гибридное: драйверы KDRV вынесены в Ring 3, остальное в ядре |
| HAL | ЗАЛОЖЕНО | `arch/x86_64`, `arch/arm64`, `bootinfo_*` |
| IPC | ЗАЛОЖЕНО | порты и общая память в ядре передают байты; формат сообщений программ — CBOR: `userland/kmsg.h` (детерминированная запись, строгий разбор, мусор отвергается кодом ошибки), проверка в QEMU (`test ipc`: 200 обменов и 3 испорченных сообщения) и фаззинг на хосте (`tests/kmsg_test.c`). Остальные службы (файловый сервер, графика) пока на своих форматах |
| IOMMU / DMA | РАБОТАЕТ (x86 и ARM64) | Intel VT-d: `iommu.c`, `iommu_vtd.c`, `drivers/iommu/intel_vtd.c`. AMD-Vi: `iommu_amd.c` (регистры, кольца команд и событий, домены), `drivers/iommu/amd_vi.c` (IVRS, DTE, страницы v1; тест `tests/amdvi_test.c` с фаззингом). Проверено в QEMU (`tests/amdvi_boot_test.sh`: диск работает через домен, запись в невыданную память блокируется). Только QEMU: на настоящем AMD не проверялось. QEMU не пишет событие нарушения, поэтому принуждение подтверждается пробной записью в невыданную страницу (`virtio_blk.c`, `canary_check`). Не сделано: перемапирование прерываний, IVMD-диапазоны (устройство с ними не изолируется), сегменты PCI > 0. ARM SMMUv3: `iommu_smmu.c` (домены, очереди команд и событий), `drivers/iommu/arm_smmu.c` (запуск, очереди), `drivers/iommu/smmu_dom.c` (STE, CD, таблицы страниц первой стадии; тест `tests/smmu_dom_test.c`); сценарий `arm64-smmu` в QEMU (`virt,iommu=smmuv3`): диск работает через домен, нарушения приходят событиями F_TRANSLATION. Первая стадия выбрана потому, что у QEMU 8.2 второй нет. Не сделано: вторая стадия, подпотоки (SSID), прерывания очередей, SMMU за не-PCI устройствами (при их наличии SMMU не включается), не-когерентный DMA (SMMU не включается). Только QEMU, на настоящем железе не проверялось |
| WASM-рантайм | РАБОТАЕТ | см. §1 |
| KIRA IR / SSA | РАБОТАЕТ | `kcc/ir.c`, `kcc/opt.c`; текстовый формат версии 1 зафиксирован: `KIRA_IR.md`, эталон `tests/kcc/ir_golden`, интерпретатор `tests/kcc/irrun.c`. IR линейный с виртуальными регистрами, не SSA в строгом смысле |
| MLIR | РЕШЕНИЕ | не вводится, условия возврата — в `ADR-0001-ir-mlir-zig-spark.md` |
| CAS / Merkle DAG | РАБОТАЕТ | `cas.c`: дерево Меркла RFC 6962, хранилище по содержимому, тест `tests/cas_test.c`. В деле: «печать системы» (`sysseal.c`, `kfstool seal`, команда `verify`, строка `[KIRA SEAL]` при загрузке; подпись издателя Ed25519 в `/etc/system.sig`, домен SEAL, проверяет `kdrv_seal_sig_check`; образы из CI без подписи, подписывает владелец ключа офлайн: `tools/kdrvsign.py --domain seal`). Хранилище по содержимому (`cas.c`) к KiraFS напрямую не подключено: общие блоки сделаны на уровне KiraFS (см. Copy-on-Write) |
| Copy-on-Write и дедупликация | РАБОТАЕТ | `kfs_clone` (команда `cp` на системном диске): копия файла делит с оригиналом то же дерево блоков, место не занимается. Файлы в KiraFS и так заменяются целиком новыми блоками, поэтому общие блоки никогда не меняются на месте. Счётчик ссылок восстанавливается при монтировании по инодам (как карта блоков), на диске не хранится; обрыв питания на каждой записи проверен тестом `tests/kfs_cow_test.c`. Дедупликация при записи: в иноде хранится SHA-256 файла, при монтировании строится индекс хэшей; запись файла с тем же содержимым не занимает новых блоков (делит дерево с существующим). Не сделано: изменение файла «на месте» |
| LSM / B+Tree | ОТЛОЖЕНО | индекс каталогов KiraFS; сначала нагрузочные измерения |
| Async I/O | ОТЛОЖЕНО | очереди запросов в драйверах Ring 3; зависит от IPC без блокировки |
| Zero-copy | ОТЛОЖЕНО | общая память через capability; зависит от IOMMU и IPC |

## 3. Форматы

| Формат | Статус | Что есть / что дальше |
|---|---|---|
| ELF | РАБОТАЕТ | `elf.c` |
| UELF | РЕШЕНИЕ | не отдельный формат, а строгий профиль ELF64 для Ring 3 (EXEC, фиксированная база, сегменты ≤ 16), который уже принудительно проверяет `elf.c`; профиль описан здесь, второго загрузчика не заводим |
| WASM, WASI | РАБОТАЕТ | см. §1 |
| FDT/DTB | РАБОТАЕТ | `fdt.c` |
| ISO, IMG | РАБОТАЕТ | `tools/mkiso_own.sh`, образы диска |
| KiraFS | РАБОТАЕТ | `kfs.c` |
| CBOR | РАБОТАЕТ | `cbor.c` (RFC 8949): детерминированная форма, строгий режим, фаззинг; тест `tests/cbor_test.c`. В деле: формат манифеста печати системы `/etc/system.cbor`. Сообщения портов в `userland/kmsg.h` на CBOR; остальные службы пока нет |
| FlatBuffers, Cap'n Proto | РЕШЕНИЕ | не вводятся: CBOR закрывает задачу без кодогенерации. Пересмотр, если понадобится zero-copy доступ к большим структурам |
| Zstd | РАБОТАЕТ (декодер; сжатые файлы в KiraFS) | В деле: обои хранятся как `/etc/wallpaper.kwp.zst` и распаковываются ядром при загрузке (1,77 -> 1,21 МБ). `zstd.c` (RFC 8878): 37 эталонных кадров уровней 1–19, контрольные суммы, многокадровость, потоковая выдача, отказ на битых и усечённых данных; тест `tests/zstd_test.c`. Сжатые файлы в KiraFS: флаг в иноде, размер = распакованный, читаются с распаковкой целиком (`kfs_write_packed` проверяет кадр распаковкой; `kfstool putz`, `tools/kput.sh`); так хранится `/etc/ssl/roots.der`. Кодера на устройстве нет |
| PEM/DER | ЗАЛОЖЕНО | DER-разбор — в `userland/x509.c` (цепочки TLS); PEM-обёртка как отдельный модуль не вынесена |
| YAML/JSON | ОТЛОЖЕНО | конфиги пока в простых текстовых форматах; JSON-разбор понадобится вместе с Python/Bash |
| Arrow, Parquet | ОТЛОЖЕНО | нужны только для аналитики Mind; зависят от Zstd (готов) и схем |
