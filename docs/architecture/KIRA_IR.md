# KIRA IR: формат, версия 1

KIRA IR - внутреннее представление компилятора KCC: линейный код с виртуальными регистрами (не SSA). Его текстовый вид
(`kcc -S-ir`, после оптимизаций `-S-oir`) - стабильный формат: его читает интерпретатор `tests/kcc/irrun.c`
(результат программы сверяется с тем же кодом, собранным clang), а вывод для образца `tests/kcc/ir_golden/sample.c`
сверяется с эталоном `sample.ir` в тесте `tests/kcc/run.sh`. Менять формат можно только осознанно: правится код,
эталон и этот документ (версия 1 -> 2).

## Модель
- Файл начинается строкой `; kcc IR`. Дальше записи верхнего уровня: `func`, `data`, `extern func`, `extern data`.
- Виртуальный регистр `%N` хранит 64 бита. Целое размером меньше 8 всегда лежит в каноническом виде (расширено знаком или нулями по типу).
- Локальные переменные - стековые ячейки `slotN` (доступ только через `laddr` + `load`/`store`); до оптимизации все переменные в памяти.
- Метки `.LN:`, переходы на метки внутри функции. Ширина `w` - байты: 1, 2, 4, 8. Суффикс `s`/`u` - знаковая/беззнаковая операция.

## Верхний уровень
```
func ИМЯ [static] params=N
  slotK: size=S align=A ИМЯ[ (param)]
  ...инструкции...
end
data ИМЯ size=S align=A [static] (data|rodata|bss) [val=V]
  bytes XX XX ...            (до 32 байт в строке)
  reloc +СМЕЩЕНИЕ -> СИМВОЛ[+-ДОБАВКА]
extern func ИМЯ
extern data ИМЯ size=S
```

## Инструкции
| Запись | Смысл |
|---|---|
| `%d = const V` | константа |
| `%d = gaddr СИМВОЛ` / `%d = laddr slotK` | адрес глобала / ячейки |
| `%d = param K [float\|double]`, `param.agg K size=S into [%a]` | K-й параметр (агрегат копируется по адресу) |
| `%d = load[.v].W[s\|u] [%a]`, `store[.v].W [%a], %b` | чтение/запись в память; `.v` - volatile |
| `%d = mov %a` | копия |
| `%d = ОП.W[s\|u] %a, %b` | ОП: add sub mul div mod and or xor rol shl shr |
| `%d = neg.W[s\|u] %a`, `not.W[s\|u] %a` | унарные |
| `%d = cmp.ОП[s\|u] %a, %b` | сравнение: eq ne lt le (результат 0/1) |
| `%d = ext.W[s\|u] %a` | расширение до 64 бит из ширины W |
| `jmp .L`, `brz %a, .L`, `brnz %a, .L` | переходы |
| `[%d =] call СИМВОЛ(%a,...) [varargs] ret=W[s\|u] [retagg=S into [%r]] [argK=aggS] [fret=F] [fargK=F]`, `call *%a(...)` | вызов |
| `ret [%a]`, `ret.agg %a` | возврат |
| `copy [%dst], [%src], N`, `zero [%a], N` | копирование и обнуление N байт |
| `asm "ШАБЛОН" out(%..) in(%..)` | встроенный ассемблер |
| `unreachable` | недостижимая точка |
| `[%d =] atomic.ОП.W[s\|u] [%a], %b, %c` | атомарные: load store xchg cas add sub and or xor nand fence (seq_cst); для cas `%b` - ожидаемое, `%c` - новое |
| `%d = vainfo K` | сведения о variadic-аргументах (0 - область регистров, 1 - первый аргумент в стеке, 2 - занято регистров) |
| `%d = alloca %a`, `%d = spsave`, `sprest %a` | динамический стек; такие функции не оптимизируются и не встраиваются |
| `%d = fОП.W %a, %b` (add sub mul div), `fneg/fsqrt/fabs.W`, `fcmp.ОП.W` | вещественные (W = 4 float, 8 double); значение в vreg - битовый образ |
| `i2f.W[s\|u]`, `f2i.W[s\|u]`, `f2d`, `d2f` | преобразования вещественных |

Вещественные операции для оптимизатора непрозрачны. Сборка с `-mno-sse` (ядро) отвергает любые вещественные конструкции.

## Что не входит в формат версии 1
- Бинарной формы нет: текстовый вид - единственный обменный. Если понадобится компактная форма, она будет описана как версия 2 поверх тех же операций.
- Стабильность относится к операциям и их записи, а не к номерам регистров и меток: номера зависят от порядка генерации.
