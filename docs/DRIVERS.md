# Слой драйверов (проект, раунд 2)

## Что возможно и что нет (честно)
- Драйверы Windows (бинарные .sys/NDIS) и модули ядра Linux (.ko, GPL, привязаны к внутренностям Linux) подключить нельзя: нужен целый чужой ядерный интерфейс. Не делаем.
- Берём ИСХОДНИКИ драйверов под лицензией BSD (FreeBSD, OpenBSD, NetBSD): их можно пересобрать под себя. GPL-код (Linux) в ядро и в образ не берём, пока не решён вопрос лицензии проекта.
- РЕШЕНИЕ ВЛАДЕЛЬЦА (01.11): драйверы не собираются на GitHub. Сначала пишется компилятор C на самой Кире (`kcc`, docs/PLAN.md, дорожка M), затем утилита `drvget`: по имени скачивает исходники BSD-драйвера по HTTPS, пересобирает их `kcc` со слоем совместимости `kdrv_bsd.h` и ставит в `/drv` на постоянном диске. Ключ подписи и workflow сборки не нужны.
- Драйверы работают в Ring 3 / EL0 как обычные программы с особыми правами (caps.h): ошибка драйвера не роняет ядро. Без IOMMU устройство с DMA всё равно может писать в любую память — это ограничение железа, его нельзя убрать программно; пакет драйвера подписан, установка идёт только из подписанных пакетов.

## Формат установленного драйвера
`/drv/NAME.kdrv` = ELF драйвера + заголовок: имя, версия, список PCI (vendor:device или class), запрашиваемые права (CAP_MMIO, CAP_IRQ, CAP_DMA, CAP_PCIDEV, CAP_NETDEV). Рядом `/drv/NAME.rec`: источник, SHA-256 исходников и ELF, дата, подтверждение пользователя. Подписи Ed25519 нет: доверие даёт явное подтверждение при установке и проверка хэша при каждой загрузке.

## Интерфейс ядра для драйвера (пакет K)
Менеджер драйверов `drvd` (ядро): при поиске устройств PCI, для которого нет встроенного драйвера, ищет в `/drv` подходящий `.kdrv`, проверяет подпись, запускает программу с правами, которые пакет просит и которые подтверждены подписью. Системные вызовы (только для устройства, закреплённого за драйвером):
- `pci_cfg_read/write(offset)` — конфигурационное пространство своего устройства;
- `mmio_map(bar)` — отобразить BAR в адресное пространство драйвера (без исполнения, без кэша);
- `dma_alloc(bytes)` → виртуальный и физический адрес непрерывной памяти; освобождается при гибели драйвера;
- `irq_wait(timeout)` — ждать прерывания устройства (MSI/MSI-X/INTx);
- `netdev_register(tx_ring, rx_ring, mac)` — сетевая карта отдаёт ядру кольца в общей памяти; сетевой стек ядра (net.c) работает с ней как со встроенной.
Библиотека для драйверов `userland/kdrv.h/.c` и общая заглушка-слой `userland/kdrv_bsd.h` (маленький слой совместимости для BSD-драйверов: bus_space, DELAY, malloc, mtx, ifnet-лайт) — во втором шаге (порт rtl8139).
Проверка: тестовый драйвер `drvloop` (виртуальное устройство-пара) и, как только каркас готов, порт `rl(4)` для RTL8139 (QEMU `-device rtl8139`).

## Окно «Драйверы» (drvman)
Программа Ring 3 `/bin/drvman` (docs/PROGRESS.md, пакет DM): список PCI (чтение ядра, право `CAP_PCILIST`), пакеты `/drv`, поиск/установка/удаление через код drvget, запуск и остановка через `FS_OP_DRV_START/STOP`. Ядро ничего не рисует и не скачивает.


## KIRA Source Intake (новое направление, исследовательский прототип)

Старый `drvget` и формат `.kdrv` остаются механизмом установки уже собранных исполняемых драйверов. Их текущая политика BSD/MIT/ISC не означает, что KIRA должна отказываться принимать исходники Linux или других проектов.

Новый отдельный этап — **Source Intake**:
- принимает открытые исходные архивы, включая GPL-лицензированные, для сохранения и технического анализа;
- сохраняет исходные файлы, LICENSE/NOTICE, SPDX-метки, источник и SHA-256;
- не запускает импортированные скрипты сборки;
- не требует, чтобы API уже был совместим с KIRA;
- формирует `.ksrc` с отчётом о лицензии, совместимости и следующих шагах.

Важно: `.ksrc` — архив исходников, а не драйвер для запуска. Наличие исходников в KIRA не означает, что их можно распространять в составе бинарного дистрибутива. Это решается отдельной проверкой лицензии и юридической политики проекта. Даже успешно собранный ELF не запускается до проверки ABI, прав, изоляции, DMA/IOMMU, тестов и подписи релизного пакета.

Текущая реализация `drvget` пока не заменена и по-прежнему отклоняет GPL при сборке/установке `.kdrv`. Это сознательно оставлено без изменений до отдельного лицензионного и технического решения. Исследовательский прототип находится в `tools/kira_source_intake.py`; тесты — `tests/test_source_intake.py`.
