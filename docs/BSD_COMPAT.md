# Слой совместимости BSD («автодрайверы»): основание

Цель: Кира сама находит драйвер устройства в открытых BSD-деревьях, скачивает его, собирает KCC на устройстве и запускает как драйвер Ring 3,
без рецептов под конкретное устройство. Пробный запуск и откат — до постоянной установки; постоянная установка — только после подтверждения человека
(защиты DMA для большинства устройств пока нет, подписей у чужих исходников нет).

## Что нужно драйверу BSD
Стандартный драйвер OpenBSD (`sys/dev/pci/if_*.c`, `sys/dev/ic/*.c`) ждёт ядро OpenBSD: `sys/param.h`, `sys/systm.h`, `sys/device.h` (autoconf, softc),
`sys/mbuf.h` (цепочки пакетов), `net/if.h` (ifnet, ifq), `net/if_media.h` (ifmedia), `dev/mii/*` (PHY), `machine/bus.h` (bus_space, bus_dma),
`dev/pci/*` (pci_mapreg_map, pci_intr_*), `sys/timeout.h`, `sys/malloc.h`. Измерение на `ne2k` (QEMU ne2k_pci): около 50 разных вызовов на ~2100 строк.

## Устройство слоя (дорожка B)
- `kcc/include/bsd/...` — заголовки с именами BSD (`<sys/param.h>`, `<net/if.h>`, `<machine/bus.h>` ...). Это НАШ код, BSD-лицензия, чужого кода в нём нет.
- `userland/bsd_rt.c` — рантайм в процессе драйвера: mbuf, ifnet/ifq поверх колец netdev (`kdrv_bsd.h`), timeout, autoconf-обвязка (`struct device`, softc),
  ifmedia, bus_space (порты и память), основной цикл (прерывание/опрос → `*_intr`, таймеры, передача `if_start`).
- `tools/bsd_pcidevs.py` (позже `drvget`) — `pcidevs.h` ТОЛЬКО из тех PCI_VENDOR_*/PCI_PRODUCT_*, что упомянуты в исходниках драйвера, значения из `pcidevs` дерева.
- Поиск драйвера по ID (vendor:device): `pcidevs` → символ `PCI_PRODUCT_*` → драйвер, где символ упомянут в таблице устройств.
- Лицензия и подозрительные файлы проверяются как у `drvget` (BSD/MIT/ISC; без GPL и бинарников).

## Корпус и счётчик совместимости
`drivers/bsdcorpus/manifest.txt` закрепляет коммит OpenBSD и SHA-256 каждого файла; `tools/bsd_corpus.py fetch` скачивает в `build-bsd/corpus` (в репозиторий чужой код не кладём).
`tests/bsd/meter.sh` собирает каждый набор слоем и пишет «собирается / не собирается» с первой ошибкой. Порядок наборов — по возможности проверки в QEMU:
1. `ne2k` (ne2k_pci: порты, без DMA, без PHY-цепочки) — основание слоя: mbuf, ifnet, bus_space, timeout, autoconf.
2. `pcn` (AMD PCnet: DMA, кольца) — bus_dma.
3. `fxp` (Intel 82557/8/9: MII, DMA) — MII/ifmedia.
4. `dc` / `tulip`, затем остальные из pcidevs.

## Что остаётся честным ограничением
Прерывания: INTx и MSI доступны драйверам Ring 3 с правом `irq` (INTx - через IOAPIC, общие линии, маскирование самого устройства битом INTX_OFF), без права - опрос раз в 10 мс.
DMA: драйвер видит только блоки `kdrv_dma_alloc` (при VT-d - свой домен). bus_dma в слое - копирование через промежуточные блоки, кластеры mbuf берутся из
памяти DMA (копий нет); DMA когерентный, на ARM64 слой DMA пока не годится. Один сетевой адаптер на стек. Общий PHY IEEE 802.3 вместо отдельных phy-драйверов OpenBSD.
Хранилища firmware нет (`loadfirmware` даёт ENOENT): драйверы, которым микрокод необязателен, работают без него.

## Состояние (ne2k)

Работает на QEMU `-device ne2k_pci` без правок исходников OpenBSD: `if_ne_pci.c + ne2000.c + dp8390.c + rtl80x9.c` из закреплённого корпуса,
`tools/bsd_build.sh` собирает ELF, пакет `bsdne` (права MMIO, PCIDEV, NETDEV) запускается менеджером драйверов, ядро получает карту,
DHCP и ping идут через неё (сценарий `drv-bsd-ne2k`). Порты - системный вызов `KDRV_SYS_IO` (сценарий `drv-io`).
`tests/bsd/meter.sh` - счётчик: сколько файлов корпуса компилируется через слой.
Уроки счётчика: без `BYTE_ORDER/LITTLE_ENDIAN` в слое `#if BYTE_ORDER == BIG_ENDIAN` молча истинно - драйвер переставлял байты.
Не сделано: сборка этого драйвера компилятором KCC (пока clang), автоматический поиск по ID в drvget (есть `tools/bsd_pcidevs.py find/ids`),
набор dc; таблица групповых адресов ядра не передаётся (принимаются все).

## DMA и прерывания (pcn, fxp)

- `pcn` (AMD PCnet, QEMU `-device pcnet`): работает на q35 с VT-d (`-device intel-iommu,aw-bits=48`) и с прерываниями INTx; сценарий `drv-bsd-pcn`
  проверяет собственный домен VT-d для карты, DHCP, ping, счётчик `irq` > 0 без шторма. Исключение слоя: QEMU отдаёт APROM (MAC) в 32-битном режиме только
  двойными словами, поэтому байтовое чтение APROM у 1022:2000 выполняется как dword.
- `fxp` (Intel 82559, `-device i82559er`): DHCP и ping работают в режиме опроса (сценарий `drv-bsd-fxp`). ОТКРЫТО: с INTx приём застревает после нескольких
  кадров (при опросе тот же код работает), причина не найдена; пакет собирается без права `irq`.
- `dc` (DEC 21143, `-device tulip`): исходники компилируются и собираются в ELF (65 КБ), драйвер находит карту, читает MAC и PHY, приёмник входит в
  состояние «ждёт кадр». ОТКРЫТО: кадры через карту не идут (watchdog передачи, приёма нет), QEMU не выставляет бит «передатчик остановлен» (драйвер
  печатает «failed to force tx to idle state»). Пакет в образ НЕ включён и сценария нет, пока драйвер не проверен.
- Уроки: ревизия PCI берётся из настоящего регистра класса (иначе fxp принимает карту за i82557); буфер, в который устройство и драйвер пишут одновременно
  (дескриптор приёма внутри кластера fxp), нельзя копировать через промежуточный блок - поэтому кластеры лежат в памяти DMA; счётчик совместимости считает
  неявное объявление функции ошибкой.

## Автоустановка по идентификатору (сценарий drvget-bsd, пройден)

Цепочка на устройстве: рецепт и файлы OpenBSD по TLS -> SHA-256 каждого файла и сверка лицензий -> сборка встроенным kcc одним модулем
(`#pragma kcc unity`, файл `kdmain.c` подключает файлы драйвера и `bsd_rt.c`) -> установка в /drv после подтверждения хешем -> при загрузке
драйвер находит карту по PCI-ID, даёт ядру DHCP и ping. Рецепты создаёт `tools/bsd_recipe.py` из индекса `drivers/bsdcorpus/index.txt`
(`tools/bsd_index.py`: 60 PCI-сетевых драйверов OpenBSD, ID -> файлы). Индекс и рецепты - из CI, не с устройства: у raw.githubusercontent.com нет
списка каталогов. `tools/bsd_meter.py` показывает честный счёт: из 60 драйверов целиком компилируется 1 (ne); остальным нужны bus_dma и IOMMU,
`if_rxring`, `sys/sockio.h`, `vlan.h` и др. Лицензии: сканер drvget принимает BSD/MIT/ISC и, отдельным решением, точный текст лицензии
Гринмана (dp8390, ne2000); отменить - убрать блок в `dg_scan_source`.
