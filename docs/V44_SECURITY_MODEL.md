# KIRA OS v44 — модель доверия для сети, приложений и USB

## Границы модели

Цель — не объявить любой внешний объект «безопасным» после одной проверки, а ограничить последствия ошибки или злонамеренного содержимого. SHA-256 обнаруживает несовпадение данных с известным эталоном; TLS аутентифицирует сетевой узел в рамках PKI; цифровая подпись связывает артефакт с ключом издателя. Ни один из этих механизмов не доказывает, что код не содержит вредоносной логики.

## Текущее состояние v43

### Сеть
- В пользовательском пространстве есть собственный TLS 1.3 клиент, проверка цепочки X.509, имени узла и CertificateVerify; реализована обработка OCSP stapling.
- drvget получает исходники по HTTPS и использует системное хранилище корней.
- Тесты TLS/X.509 покрывают положительные и отрицательные случаи, включая неподтверждённый сертификат и OCSP.
- Это не является полным аудитом DNS, всех redirect-политик, сетевых парсеров или всех malformed inputs. HTTPS не подтверждает безопасность содержимого репозитория.

### Приложения
- Встроенные системные приложения проверяются по SHA-256 манифесту, встроенному в ядро.
- Это защищает от подмены относительно образа, но не является подписью издателя и не создаёт доверенную цепочку загрузки от прошивки.
- Пользовательская ELF-программа, запускаемая явно через локальный механизм, получает нулевой набор capability; код всё равно может повреждать собственные данные и использовать уязвимости ядра/системных вызовов.
- В текущем слое нет полноценного подписанного формата обновления с ключами выпуска, отзывом и anti-rollback.

### USB и внешние накопители
- USB Mass Storage проходит через BOT/SCSI, затем обнаруживается таблица MBR/GPT и FAT-разделы; FAT автоматически монтируется в `/usbN`.
- Текущий VFS допускает запись, создание каталогов и удаление на смонтированных FAT-томах. По умолчанию read-only режим пока не обеспечен.
- HID-устройства могут временно задерживаться до решения USB-политики/«Разума»; это отдельный путь от Mass Storage.
- Автоматическое выполнение программ с USB не является штатным сценарием проводника, но это не заменяет ограничения записи и безопасного парсинга.
- Отдельная защита от DMA-устройств USB/PCI зависит от аппаратной изоляции; без IOMMU программная политика не устраняет произвольный DMA.

## Требования v44

1. USB Mass Storage монтируется read-only по умолчанию; запись требует явного осознанного переключения пользователем для конкретного тома.
2. Не выполнять autorun, обработчики запуска и установку программ при подключении носителя.
3. Проверять границы и переполнения в USB descriptors, BOT/CSW, SCSI responses, MBR/GPT и FAT; fuzz malformed descriptors, partition tables, directory entries и LFN.
4. Пакеты приложений должны иметь канонический манифест, подпись доверенным ключом KIRA, ограничения ABI/capabilities, версию и защиту от отката.
5. Скачанные программы помещать в карантин; TLS + проверка подписи + ручное подтверждение перед установкой. Не считать проверку антивирусным сканером заменой изоляции.
6. Для приложений — минимальные права, отдельное адресное пространство, NX/W^X, ограничение системных вызовов и контролируемый доступ к файлам/устройствам.
7. Для сети — строгая обработка TLS/X.509 ошибок, hostname, срока действия, времени, redirect policy, DNS и ограничения размера/числа элементов при разборе ответов.
8. Любое обновление должно иметь проверяемый подписанный манифест, возможность отзыва ключа и безопасного восстановления предыдущей версии.

## Непереговорные ограничения

- Не включать Linux kernel, Linux-модули или Linux runtime в KIRA.
- Внешний исходный код не становится собственным после переименования. Проверять лицензии и notices по каждому файлу.
- Не давать сетевым загрузкам автоматически исполняться с правами ядра или системными capabilities.
- Не заявлять «полную защиту» только на основании SHA-256, TLS, антивирусного сканирования или QEMU.
