# Изоляция приложений KIRA OS

## Текущая основа

- Каждый Ring 3 / EL0 процесс получает отдельное адресное пространство.
- ELF-сегменты отображаются с W^X: код RX, данные RW-NX, константы R-NX; стек RW-NX.
- Системные возможности выдаются по доверенному манифесту приложения; неизвестные программы получают нулевой набор прав.
- Дескрипторы IPC хранятся в таблице конкретного процесса.

## Первая граница межпроцессного IPC

Именованные порты и разделяемая память больше не должны быть автоматически доступны всем приложениям с CAP_IPC.

- Новый объект по умолчанию приватный: открыть его может только PID-создатель.
- Создатель может явно опубликовать объект флагом KOPEN_PUBLIC при создании.
- Публикацию нельзя добавить задним числом при открытии уже существующего приватного объекта.
- Открытие чужого приватного объекта возвращает KE_PERM.
- Уже выданный дескриптор остаётся отдельным полномочием процесса; доступ через него не зависит от повторного поиска имени.

Это начальный уровень доменной изоляции, а не полная реализация Qubes OS или seL4. Процессы пока разделяют одно ядро и его доверенную вычислительную базу; виртуальные машины на приложение, capability-transfer через IPC и формальная верификация ядра в этот этап не входят.

## Проверка

Хостовый тест объектов проверяет приватные и публичные порты и области памяти, запрет повышения публичности при открытии, повторное открытие владельцем и освобождение объектов.
