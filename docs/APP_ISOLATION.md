# Изоляция приложений KIRA OS

## Текущая основа

- Каждый Ring 3 / EL0 процесс получает отдельное адресное пространство.
- ELF-сегменты отображаются с W^X: код RX, данные RW-NX, константы R-NX; стек RW-NX.
- Системные возможности выдаются по доверенному манифесту приложения; неизвестные программы получают нулевой набор прав.
- Дескрипторы IPC хранятся в таблице конкретного процесса.

## Первая граница межпроцессного IPC

Именованные порты и разделяемая память больше не должны быть автоматически доступны всем приложениям с CAP_IPC.

- Новый объект по умолчанию приватный: открыть его может только PID-создатель.
- Создатель может явно опубликовать объект флагом KOPEN_PUBLIC при создании.
- Публикацию нельзя добавить задним числом при открытии уже существующего приватного объекта.
- Открытие чужого приватного объекта возвращает KE_PERM.
- Уже выданный дескриптор остаётся отдельным полномочием процесса; доступ через него не зависит от повторного поиска имени.

Это начальный уровень доменной изоляции, а не полная реализация Qubes OS или seL4. Процессы пока разделяют одно ядро и его доверенную вычислительную базу; виртуальные машины на приложение, capability-transfer через IPC и формальная верификация ядра в этот этап не входят.

## Домены приложений (без гипервизора)

Приложение живёт в одном из доменов (`caps.h`, таблица в `caps.c`): system, driver, media, net, tools, untrusted. Изоляция процессами и адресными пространствами, виртуализации железа (VT-x / AMD-V) нет, и она не нужна: все программы работают в Ring 3 / EL0 под одним ядром.

- Потолок прав: права программы из таблицы `caps.c` ограничиваются потолком домена при запуске. Ошибка в таблице не даст media-программе сеть, а net-программе окно.
- Квота: домен держит не больше заданного числа процессов одновременно (`domain_proc_max`); сверх квоты запуск отказывает с записью в журнал.
- Общие объекты: порт или память с `KOPEN_PUBLIC` открывает только свой домен и system. Другие домены получают `KE_PERM` даже при наличии `CAP_IPC`. Приватные объекты по-прежнему только у создателя.
- Собранные пользователем программы (`local-*`), неизвестные имена и подписанные внешне образы (без прав) - домен untrusted с нулевым потолком. Драйверы Ring 3 - домен driver с потолком `CAP_DRIVER_`.
- Проверки: `tests/domain_test.c` (потолок каждой записи таблицы, достижимость), `tests/kobj_test.c` (порты и память между доменами), сценарий QEMU isolation (`ipcx` из media не открывает общую память `ipc` из tools), ARM64 - `ci/arm64_vm.py`.
- Приложения на WASM-модулях (`wasm`, домен tools) живут внутри своего процесса: у модуля нет ничего, кроме того, что рантайм выдаёт через WASI.

Не сделано: квоты памяти и потоков на домен (сейчас только процессы), отдельные пространства имён файлов по доменам.

## Сквозная проверка в виртуальных машинах

- x86-64/KVM: сценарий isolation прошёл; второй процесс получил KE_PERM на чужие приватные порт и SHM, затем завершил 200 round trips. Отдельно прошли проверки адресных пространств, пользовательского указателя на kernel memory и capability-прав.
- AArch64/QEMU TCG: arm64-gicv3 прошёл ту же проверку приватных IPC/SHM и 200 round trips; arm64-isolation также PASS.
- Эти результаты подтверждают текущие сценарии, но не доказывают эквивалентность Qubes/seL4, не покрывают capability transfer/revocation и не подтверждают физическое железо.

## Проверка

Хостовый тест объектов проверяет приватные и публичные порты и области памяти, запрет повышения публичности при открытии, повторное открытие владельцем и освобождение объектов.
