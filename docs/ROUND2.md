## J. Разум: больше рычагов, самостоятельность, обучение (ветка pkg-J)
Файлы: mind.c, mind_sys.c, mindnet.c, experience.c, mind.h, docs.
1. Рычаги 13+ (минимум 18 новых, всего не меньше 30; решение владельца), каждый с измеримым сигналом, безопасными границами и откатом, если стало хуже («не вреди»). Кандидаты: размер кэша блочных устройств / упреждающее чтение; размер буфера звука (задержка против недоборов); окно и буферы TCP; миграция потоков между ядрами / привязка; приоритет программ с неравномерным профилем; режим простоя ядер (halt/mwait); частота опроса устройств без прерываний; очередность дисковых запросов; сжатие журналов/опыта. Арбитраж: за раз проверяется один рычаг (или независимые по сигналам), бюджет изменений в минуту, общий откат при росте опозданий экрана. Каждый рычаг — строка в `ai levers`, запись в журнал решений (`ai why`), сценарий стенда, где рычаг сработал и откатился.
2. Самостоятельность: управление включено по умолчанию там, где есть откат; режим «наблюдение» остаётся; эксперименты (A/B) выбирают значение рычага по замеру; Разум сам помечает рычаг «не помогает» и перестаёт его трогать до смены нагрузки.
3. Обучение в GitHub: сценарий-тренажёр `mind-train` (долгая нагрузка разных типов: спам программ, диск, сеть, звук, 3D), по окончании извлекает файл опыта из образа диска (kfstool) и сохраняет как артефакт; отдельный workflow `mind-train.yml` (workflow_dispatch) собирает его в `data/mind_seed.bin`. Ядро при первой загрузке без сохранённого опыта берёт семя как априорное знание: веса модели предвидения и пороги рычагов, но НЕ абсолютные нормы устройства (они зависят от железа); доверие к семени ограничено (число наблюдений в семени урезано), реальный опыт перекрывает его. В отчёте честно: семя получено в QEMU и на железе будет только стартовой подсказкой.
Проверка: хост-тесты mind (расширить tests/), стенд mind-levers (x86, ARM где применимо), mind-train (долгий, отдельный job, не в основном матрице).

## K. Каркас драйверов (ветка pkg-K) — читать docs/DRIVERS.md (он главнее; подписей нет, решение владельца)
Сделать: права CAP_MMIO/CAP_IRQ/CAP_DMA/CAP_PCIDEV/CAP_NETDEV (caps.h) и системные вызовы из DRIVERS.md (x86-64 и ARM64, где есть PCI: ECAM), менеджер `drvd`: ищет в `/drv` файлы `NAME.kdrv` (ELF + заголовок kdrv_format.h: имя, версия, список PCI vendor:device/class, запрашиваемые права) и `NAME.rec` (SHA-256 ELF, источник, подтверждение); при поиске устройства PCI без встроенного драйвера сверяет хэш ELF с .rec и запускает драйвер как процесс `drv-NAME` с запрошенными правами, ограниченными ЕГО устройством (BAR, конфигурация, прерывание, DMA); библиотека `userland/kdrv.h/.c`; сетевой стек принимает NIC от драйвера через `netdev_register` (кольца в общей памяти). Тестовый драйвер `drvloop` (виртуальная пара/нулевое устройство, например virtio-rng или edu-устройство QEMU `-device edu` для MMIO/IRQ/DMA — выбери проще проверяемое), собираемый ЛЮБЫМ способом на хосте; сценарии стенда: драйвер найден по PCI-ID и запущен; драйвер с испорченным хэшем не запущен; драйвер без запрошенного права получает отказ; драйвер обращается к чужому BAR/устройству — отказ; драйвер гибнет — ядро живо, DMA и отображения освобождены. Порт rl(4) — во втором шаге после приёмки каркаса.

## L. drvget (ветка pkg-L) — ПОСЛЕ компилятора kcc (M3) и каркаса K
Сборочной фермы на GitHub нет (решение владельца 01.11). `userland/drvget.c` (обе архитектуры): `drvget install <имя|URL>` скачивает исходники BSD-драйвера (архив/файлы) по HTTPS (TLS из fetch/tls.c, корневые /etc/ssl/roots.der), проверяет лицензию (BSD/MIT/ISC) и показывает пользователю источник, SHA-256 и права, ставит после подтверждения; собирает `kcc` со слоем `userland/kdrv_bsd.h`; кладёт `/drv/<имя>.kdrv` и `.rec`; `drvget list|remove|verify`. Проверка: хост-тесты разбора и сети (ci/https_once.py), стенд: драйвер-образец из локального сервера собирается на Кире и загружается `drvd`.
