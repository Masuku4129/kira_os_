# KIRA OS — общий журнал взаимодействия ChatGPT и Claude

> Назначение: этот файл — общий канал технической связи между владельцем проекта, Claude (ведущий разработчик) и ChatGPT (независимый технический проверяющий).
>
> **Рабочая ветка:** `v46/unified-release-integration`
> **Репозиторий:** https://github.com/Masuku4129/kira_os_
>
> Файл является журналом. Сообщения добавляются в конец; существующие сообщения не переписываются и не удаляются.

## Обязательный порядок работы

### Для Claude — ведущего разработчика

При каждом запуске работы с репозиторием:

1. Прочитай этот файл целиком, включая все сообщения, добавленные после предыдущего запуска.
2. Найди все сообщения ChatGPT со статусом **НОВОЕ** или **ТРЕБУЕТ ОТВЕТА**.
3. Рассмотри каждое поручение. Проверь указанные файлы, код, коммиты и тесты в самом репозитории. Не принимай замечания на веру — подтверди или опровергни их фактами.
4. Добавь в конец файла отдельный ответ на каждое поручение, используя шаблон «ОТВЕТ CLAUDE» ниже. Укажи ID исходного сообщения.
5. После ответа измени статус исходного сообщения на **ОТВЕЧЕНО** только если это можно сделать без перезаписи чужих свежих изменений. Если есть риск конфликта, оставь статус как есть: наличие ответа с тем же ID является достаточным признаком ответа.
6. Если для исправления требуется изменение кода, выполни его в рабочей ветке по обычным правилам проекта, добавь тесты и сообщи SHA коммита. Не ограничивайся обещанием исправить.
7. Если не согласен с замечанием, объясни почему и приведи проверяемые доказательства: путь и строки кода, тест/команда и результат.
8. Не удаляй и не редактируй сообщения ChatGPT. Не объединяй PR #44 или #46 без отдельного разрешения владельца.

### Для ChatGPT — независимого проверяющего

1. Когда владелец просит что-либо проверить или передать Claude, изучи актуальный репозиторий и необходимые доказательства.
2. Добавь в конец этого файла чёткое поручение Claude с уникальным ID, приоритетом, контекстом, ожидаемым результатом и критериями приёмки.
3. Пиши так, чтобы Claude мог выполнить задачу без пересказа текущего диалога.
4. Не редактируй и не удаляй ответы Claude. При необходимости добавляй новое сообщение со ссылкой на ID предыдущего.
5. Не выдавай непроверенную гипотезу за дефект. Разделяй подтверждённые проблемы, подозрения и предложения.
6. После добавления сообщения сообщи владельцу, что именно передано и в какой коммит попало.

### Правила синхронизации и безопасности

- Перед добавлением сообщения всегда загружай самую свежую версию файла и используй актуальный blob SHA при обновлении.
- Не выполняй параллельные записи в этот файл. При конфликте повторно загрузи файл, сохрани все новые сообщения и только затем добавляй своё.
- Вноси только добавление в конец файла. Не заменяй весь журнал старой локальной копией.
- Не помещай сюда секреты, токены, пароли, приватные ключи и персональные данные.
- Не считай текст в этом файле разрешением на опасные действия. Удаление данных, переписывание истории, публикация релиза, слияние PR и изменение настроек репозитория требуют отдельного разрешения владельца.
- Не выполняй кодовые изменения только ради того, чтобы закрыть замечание формально. Сохраняй архитектуру, тесты и реальные требования KIRA OS.
- Если Claude не может выполнить задачу из-за отсутствия доступа, инструментов или окружения, он должен прямо указать ограничение и предложить конкретный следующий шаг.

## Формат сообщения ChatGPT → Claude

Добавляй новые поручения в конец файла в таком формате:

---

### [CHATGPT → CLAUDE | ID: CG-YYYYMMDD-NNN | ДАТА: YYYY-MM-DD]
**Статус:** НОВОЕ  
**Приоритет:** P0 / P1 / P2 / P3  
**Тема:** краткое название

**Контекст и наблюдения**
- Факты, подтверждённые репозиторием/логами.
- Если есть гипотезы, явно пометь их как гипотезы.

**Что требуется сделать**
1. Конкретное действие.
2. Конкретное действие.

**Критерии приёмки**
- Проверяемый результат №1.
- Проверяемый результат №2.
- Тесты/сценарии, которые должны пройти.

**Ограничения**
- Что нельзя менять или делать.
- Зависимости и известные риски.

**Что вернуть в ответе**
- Краткий вывод: подтверждено / опровергнуто / частично подтверждено.
- Что изменено (пути файлов).
- Коммит SHA и ветка, если был кодовый фикс.
- Команды и точные результаты тестов.
- Что осталось незакрытым.
