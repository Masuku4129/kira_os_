# kcc — компилятор C для Киры (дорожка M)

Цель: компилировать на самой Кире BSD-драйверы (слой `kdrv_bsd.h`) и небольшие программы; результат — ELF Киры. Чистый C без внешних библиотек, пишем сами (чужой код не берём). Один и тот же код собирается хостом (clang) для тестов и Кирой для работы (Ring 3 / EL0). Память — своя арена (bump) с лимитом, без malloc ядра.

## Состав (каталог kcc/)
`pp.c` препроцессор (#include "..."/<...> через виртуальную файловую систему, #define функциональные и объектные, #, ##, __VA_ARGS__, #if/#ifdef/#elif/#else/#endif/defined, #undef, #error, #pragma once, предопределённые __KIRA__, __x86_64__/__aarch64__, __STDC_VERSION__ 199901L),
`lex.c` лексер, `parse.c` разбор в AST, `type.c` типы и проверка, `ir.c` линейный IR, `gen_x86.c` кодогенерация, `asm_x86.c` свой кодировщик машинного кода, `elf.c` запись ELF Киры (M2 готов; хост-проверка через `tests/kcc/kloader.c`), `gen_a64.c` (M4), `main.c` драйвер командной строки `kcc [-I dir] [-D n[=v]] -o out file.c...`.

## Язык (подмножество, достаточное для драйверов BSD)
C99: все типы целых, указатели, массивы, struct/union/enum, typedef, битовые поля, указатели на функции, `static`/`extern`/`inline`/`const`/`volatile`, составные литералы, назначенные инициализаторы, локальные массивы, VLA НЕ нужны. Расширения GNU, которые реально встречаются: `__attribute__((packed, aligned(N), unused, noreturn, always_inline))`, `__asm__ volatile("...")` (встраиваемый ассемблер: поддержать минимальный набор шаблонов для барьеров и in/out/rdtsc — без общего ассемблера), `typeof`, выражения-операторы `({ ... })`, `__builtin_expect/offsetof/memcpy/unreachable`. Не поддерживаются и дают понятную ошибку: VLA, `_Complex`, `_Generic`, float/double в M1–M3 (драйверам не нужны; позже).

## Этапы
- M1 (хост): pp + lex + parse + type + IR, вывод `kcc -S-ir`; тесты: корпус tests/kcc/*.c (≥150 программ: выражения, приоритеты, инициализаторы, структуры, указатели, макросы, препроцессор) — принятие/отклонение сверяется с `clang -fsyntax-only -std=c99`, значения константных выражений — с clang; fuzz на повреждённых исходниках без падений; ошибки с номером строки.
- M2 (хост): кодогенерация x86-64 без внешнего ассемблера, ELF исполняемый как у userland/ (см. userland/user.ld и ELF-загрузчик elf.c: адреса, W^X); тесты: корпус программ компилируется kcc и clang, выполняются на хосте (через тестовый загрузчик/эмулятор вызовов k_*) и дают одинаковый вывод.
- M3 (Кира): `kcc` как программа Ring 3 (userland/kcc), `cc` в консоли; libc-lite (`kcc/include`: stdint.h, stddef.h, string.h, stdio.h-лайт, stdlib.h-лайт — malloc из кучи программы, memcpy/memset/strlen и т.д.); компиляция файлов песочницы /data/kcc/; стенд: Кира собирает пример и запускает его.
- M4: AArch64-бэкенд и сборка драйвера на устройстве (`drvget`).
Правила качества: ни одной возможности «для вида»: неподдержанная конструкция даёт ошибку компиляции, не молчаливо неверный код.
