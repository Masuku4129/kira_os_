# kcc — компилятор C для Киры (дорожка M)

Цель: компилировать на самой Кире BSD-драйверы (слой `kdrv_bsd.h`) и небольшие программы; результат — ELF Киры. Чистый C без внешних библиотек, пишем сами (чужой код не берём). Один и тот же код собирается хостом (clang) для тестов и Кирой для работы (Ring 3 / EL0). Память — своя арена (bump) с лимитом, без malloc ядра.

## Состав (каталог kcc/)
`pp.c` препроцессор (#include "..."/<...> через виртуальную файловую систему, #define функциональные и объектные, #, ##, __VA_ARGS__, #if/#ifdef/#elif/#else/#endif/defined, #undef, #error, #pragma once, предопределённые __KIRA__, __x86_64__/__aarch64__, __STDC_VERSION__ 199901L),
`lex.c` лексер, `parse.c` разбор в AST, `type.c` типы и проверка, `ir.c` линейный IR, `gen_x86.c` кодогенерация, `asm_x86.c` свой кодировщик машинного кода, `elf.c` запись ELF Киры (M2 готов; хост-проверка через `tests/kcc/kloader.c`), `gen_a64.c` (M4), `main.c` драйвер командной строки `kcc [-I dir] [-D n[=v]] -o out file.c...`.

## Язык (подмножество, достаточное для драйверов BSD)
C99: все типы целых, указатели, массивы, struct/union/enum, typedef, битовые поля, указатели на функции, `static`/`extern`/`inline`/`const`/`volatile`, составные литералы, назначенные инициализаторы, локальные массивы, VLA НЕ нужны. Расширения GNU, которые реально встречаются: `__attribute__((packed, aligned(N), unused, noreturn, always_inline))`, `__asm__ volatile("...")` (встраиваемый ассемблер: поддержать минимальный набор шаблонов для барьеров и in/out/rdtsc — без общего ассемблера), `typeof`, выражения-операторы `({ ... })`, `__builtin_expect/offsetof/memcpy/unreachable`. Не поддерживаются и дают понятную ошибку: VLA, `_Complex`, `long double`. float/double поддержаны (раздел ниже).

## Этапы
- M1 (хост): pp + lex + parse + type + IR, вывод `kcc -S-ir`; тесты: корпус tests/kcc/*.c (≥150 программ: выражения, приоритеты, инициализаторы, структуры, указатели, макросы, препроцессор) — принятие/отклонение сверяется с `clang -fsyntax-only -std=c99`, значения константных выражений — с clang; fuzz на повреждённых исходниках без падений; ошибки с номером строки.
- M2 (хост): кодогенерация x86-64 без внешнего ассемблера, ELF исполняемый как у userland/ (см. userland/user.ld и ELF-загрузчик elf.c: адреса, W^X); тесты: корпус программ компилируется kcc и clang, выполняются на хосте (через тестовый загрузчик/эмулятор вызовов k_*) и дают одинаковый вывод.
- M3 (Кира, x86-64 - СДЕЛАНО, см. PROGRESS.md): `kcc` как программа Ring 3 (userland/kcc), `cc` в консоли; libc-lite (`kcc/include`: stdint.h, stddef.h, string.h, stdio.h-лайт, stdlib.h-лайт — malloc из кучи программы, memcpy/memset/strlen и т.д.); компиляция файлов песочницы /data/kcc/; стенд: Кира собирает пример и запускает его.
- M4: AArch64-бэкенд и сборка драйвера на устройстве (`drvget`).
Правила качества: ни одной возможности «для вида»: неподдержанная конструкция даёт ошибку компиляции, не молчаливо неверный код.

## Самосборка (x86-64) - СДЕЛАНО для самого компилятора, `tests/kcc/selfhost.sh`
Цепочка: stage0 (kcc, собранный gcc/clang хоста) собирает stage1 - kcc/*.c + userland/kcc.c + userland/kccrt.c одним файлом
(`kcc/selfhost/unity.c`; отдельной компоновки объектов у kcc нет) в ELF Киры; stage1 работает как программа Киры под хост-загрузчиком
`tests/kcc/kloader.c` и собирает stage2, stage2 собирает stage3. Требование: stage1 == stage2 == stage3 побайтно (проверяется), затем stage2
собирает корпус (tests/kcc/native, exec, run) и результат сравнивается побайтно с stage0.
Что для этого потребовалось: `setjmp`/`longjmp` - встроенные функции kcc (как memcpy/strlen; только x86-64), атрибут `returns_twice` принимается,
порядок вычисления аргументов в kcc/ir.c задан явно (раньше IR зависел от того, каким компилятором собран kcc), совпадающие имена двух бэкендов
переименовываются (`kcc/selfhost/ren_*.h`), условный оператор над структурами в pp.c заменён на if.
**Границы:** это самосборка только компилятора, только x86-64, под хост-загрузчиком Киры; на самой Кире в QEMU она не запускалась. Ядро, userland,
загрузчики и сборка образа по-прежнему идут через внешние Clang/LLD/NASM. Не покрыто: ассемблер для .s-файлов ядра, компоновка нескольких объектов,
самосборка под AArch64.

## Оптимизации (kcc/opt.c, бэкенд gen_x86.c)
Общий для x86-64 и AArch64 проход `ir_optimize` над линейным IR: продвижение скалярных локальных (целые, указатели) из слотов стека в
виртуальные регистры (только если адрес слота нигде не уходит; volatile и функции с setjmp не трогаются), распространение копий в пределах
базового блока, слияние вычисления с записью в переменную, удаление мёртвого кода. Переменные с несколькими определениями живут весь
цикл, который их затрагивает (иначе значение по обратному переходу терялось бы). Отключается флагом `-O0` (для сверки и отладки).
Бэкенд x86-64: операции прямо в регистре приёмника, непосредственные операнды (add/sub/and/or/xor/cmp/сдвиги, умножение на степень двойки -
сдвиг), константы без регистра, слияние сравнения с условным переходом, загрузки/записи по адресу в регистре, домашняя область аргументов
только для приходящих регистров.
**Измерено** (хост, три микротеста; время в секундах, меньше - лучше): решето 0.88 -> 0.40 (clang -O0 0.58, -O2 0.35), умножение матриц
0.39 -> 0.12 (clang -O0 0.12, -O2 0.023), хеш-цикл с вызовом малой функции 0.92 -> 0.49 (clang -O0 0.25, -O2 0.15). Сам kcc (stage3) стал
меньше на треть (571 -> 383 КБ). Основной остаток отставания - вызовы: нет инлайнинга, каждая функция сохраняет все используемые
callee-saved регистры; пул - 5 регистров (x86-64). Это не проверено на железе и не в QEMU внутри Киры: только под хост-загрузчиком
(`tests/kcc/run.sh`, `tests/kcc/selfhost.sh`, регрессии `tests/kcc/run/r_opt_*.c`).

### Результаты этапа 32-бит и слияния (измерено, kloader, секунды)
Беззнаковые 32-битные операции теперь кодируются 32-битными командами (верх обнуляется аппаратно, лишние `mov r32,r32` исчезли); MOV/EXT/NEG/NOT работают напрямую в регистре назначения; `t=op..; v=t` сливаются в `v=op..`.
sieve 0.31, matmul 0.117, хэш-цикл 0.22 (было 0.88 / 0.39 / 0.92 до оптимизатора). Остаток относительно clang -O2: нет векторизации, нет rol/ror, нет инверсии циклов, нет слияния адресации.

## Ядро, собранное KCC (измерено)
`kcc -c` выдаёт ELF64 ET_REL (x86_64); связка `ld.lld` + `nasm` для .s прежняя. Все 120 C-файлов ядра x86_64 компилируются KCC; ядро грузится собственной BIOS-цепочкой (SeaBIOS, QEMU) до консоли и Разума: `tests/kernel_kcc_boot_test.sh`.
Скорость: все 120 файлов - 0.67 с у KCC и 18 с у clang -O2 (в 27 раз быстрее). Образ ядра больше (1.74 МБ против 0.98 МБ): нет --gc-sections-эквивалента на уровне функций и слабее оптимизатор.
Не сделано: AArch64 `-c`, ассемблер для .s (остаётся nasm), SSE-встроенные тесты cpu, глобальный asm, section/used-атрибуты.

### Результаты этапа циклов и адресации (измерено, kloader, минимум из 5 запусков, секунды; clang -O2 без векторизации)
Добавлено: вынос инвариантов из циклов (только чистые операции без ловушек, вход в цикл строго сверху; загрузки не выносятся - анализа псевдонимов нет),
инверсия циклов (условие проверяется внизу, один переход на итерацию), слияние адреса в операнд памяти `[база + индекс*2^s + смещение]`
(кодировщик получил SIB), `imul r, r/m, imm32`, распознавание циклического сдвига `(x>>c1)|(x<<c2)` в `rol` (только x86-64; у AArch64 отдельный ror, пока не сделан).
Решето 0.30 (clang 0.29), хеш-цикл 0.17 (0.15), умножение матриц 0.077 (0.027). Матрица остаётся отстающим: нет понижения силы умножения по индукционной
переменной, нет развёртки, нормализация 32-битных значений после каждой операции, пул из 5 регистров.
Проверка: `tests/kcc/run.sh` (464 программы против clang), `selfhost.sh` (stage2 = stage3), `obj.sh`, ядро, собранное KCC, грузится (`kernel_kcc_boot_test.sh`);
новые регрессии `tests/kcc/run/r_licm_addr.c`, `r_rotate.c`.

### Понижение силы умножения (op_sr) - измерено, kloader, минимум из 5, секунды
Умножение `i*C` по индукционной переменной заменяется накопителем (`kcc/opt.c`, `op_sr`; `-fno-sr` отключает, `-S-oir` печатает IR после оптимизации).
4-байтный знаковый счётчик считается не переполняющимся (UB в C, как у clang/gcc), 8-байтные счётчики точны по модулю 2^64; циклы с лишними обратными переходами не трогаются.
Решето 0.31 -> 0.34 (шум, SR там не применяется), матрицы 0.075 -> 0.070 (clang -O2 0.027), хеш 0.166 -> 0.138. Выигрыш на матрицах мал: остаток отставания - развёртка, нормализация 32-битных значений после каждой операции, адреса глобалов (lea) в теле цикла.
Проверка: tests/kcc/run.sh (464 программы + fuzz), selfhost.sh, obj.sh - зелёные; новая регрессия tests/kcc/run/r_sr.c. Скорость кода по-прежнему НЕ лучше clang -O2.

### Базовые замеры против clang -O2 (tests/kcc/bench, 2026-11-08, до этапов A1–A9)
Время - минимум из 5, kcc-ELF под kloader против нативного clang -O2; размер - секция .text объекта. Все результаты верны.
bits 1.33, calls 3.56, hash 1.32, list 1.32, matmul 3.24, mlp 2.50, sha256 3.22, sieve 1.11, sort 1.24, strscan 1.55 (во сколько раз kcc медленнее).
Среднее геометрическое 1.85, худший 3.56. Код больше на >10% у 5 из 10 (sha256 и list ~1.84x). Цель плана (docs/BUILDER_PLAN.md): геом. <= 1.10, худший <= 1.25.
Главные разрывы: calls (нет межпроцедурного встраивания и устранения вызовов), matmul/mlp/sha256 (нормализация 32-бит после каждой операции, нет развёртки, пул регистров).

### Этап A1: пропуск нормализации 32-бит (op_nonorm; -fwrapv отключает часть про счётчики)
Результат 32-битной операции, который читают только 32-битные операции и store.4, не расширяется до 64 бит (точно, без допущений); шаг счётчика цикла `v = v +/- K` тоже не расширяется (переполнение знакового int не определено, как у clang).

### Ускорение (ветка kcc-perf, 2026-11-08): разбор потерь и результат
Разбор дизассемблера против clang -O2: sha256 - мало регистров в пуле и нет rol (сдвиги+or); mlp - лишняя нормализация верхней половины перед sar; calls - кадр с rbp у листовых функций и рекурсия без встраивания; bits - цикл `x &= x-1` вместо popcount; matmul - адрес в цикле пересчитывается (инвариантная часть суммы); strscan - счётчики в памяти/отсутствие развёртки.

## Широта языка: G2 (_Generic, _Alignas, __has_include)
Поддержано: `_Generic` (выбирается ветка по типу управляющего выражения без его вычисления; верхние квалификаторы отбрасываются, квалификаторы указуемых типов учитываются; массив и функция приводятся к указателю), `_Alignas(N)` и `_Alignas(тип)` в объявлениях и полях структур, `__has_include("x")` и `__has_include(<x>)` в `#if` (поиск теми же путями, что у `#include`). Тесты: tests/kcc/run/r_generic.c, r_alignas.c, tests/kcc/ok/has_include.c сверяются с clang.
Ограничения: `char` и `signed char` в kcc один тип, поэтому `_Generic` с обеими ветками даст «несколько совпадений» (у clang они разные); локальные объекты с выравниванием больше 16 по-прежнему отвергаются; `defined(__has_include)` ложно (в clang истинно).

## float/double (ветка kcc-float)
**Поддержано:** типы `float` (binary32) и `double` (binary64); литералы (десятичные, с порядком, суффикс f/F, шестнадцатеричные `0x1.8p1`); `+ - * /`, унарный минус,
сравнения со всеми правилами NaN как у clang (`<`,`<=`,`>`,`>=`,`==` ложны, `!=` истинно), `!x`, `if/while/for/?:/&&/||` по `x != 0.0`; преобразования int<->float<->double всех
ширин и знаковости (u64 корректно, в т.ч. >= 2^63: округление один раз, без двойного); обычные арифметические преобразования и продвижения; float->double в variadic;
`++ -- += ...`; глобальные/локальные/массивы/поля структур; константные выражения и статические инициализаторы (сворачиваются в `kcc/softfp.c` - целочисленная
IEEE-арифметика с округлением к чётному, подтверждена случайной сверкой с железом в `tests/kcc/softfp_test.c`); `__builtin_sqrt/sqrtf/fabs/fabsf`.
Строгий IEEE: нет переупорядочения, FMA и свёртки неконстант; операции FBIN/FUN/FCMP/FCVT непрозрачны для opt.c.
**x86-64:** SSE2 (movss/movsd/add/sub/mul/div/sqrt/ucomis/cvtsi2s/cvtts2si/cvts2s), собственный кодировщик (63 кодировки сверены с llvm-mc: `x86_sse_enc.c`),
SysV: xmm0-7, возврат в xmm0, `al` = число xmm при вызове variadic, регистры xmm - отдельный пул (xmm8-12), живые через вызов значения лежат на стеке.
**AArch64:** скалярный FP (fadd/fsub/fmul/fdiv/fneg/fabs/fsqrt/fcmp/scvtf/ucvtf/fcvtzs/fcvtzu/fcvt/fmov), v0-v7 по AAPCS64, va_list с q0-q7 (кодировки сверены с llvm-mc,
`a64_enc.c`; исполняет `a64emu.c`). Значения живут в x-регистрах/слотах как битовые образы, в v16-v18 только на время операции (быстрой FP-аллокации на a64 нет).
**Ядро без SSE:** флаг `-mno-sse` (макрос `__KCC_NOSSE__`): любые float/double - ошибка `unsupported ... (-mno-sse build)` с номером строки, ни одной команды SSE; объекты
целочисленного кода и va_list побайтно те же, что до изменений (проверено на 124 файлах ядра). `tests/kernel_kcc_boot_test.sh` и `kernel_selfbuilt_boot_test.sh` собирают с `-mno-sse`.
**Не поддержано / ограничения:** `long double` (ошибка unsupported с номером строки; x87 80 бит нет); `va_arg(ap, float)` (отвергается, как и в C); float в inline asm;
структуры по значению с float/double используют общее соглашение kcc для агрегатов (целочисленные регистры либо указатель на копию), НЕ классификацию SysV/HFA:
между кодом kcc работает (`exec/x_float_structval.c`), с чужим объектным кодом несовместимо; `irrun` не исполняет variadic и агрегаты по значению (эти тесты - в `exec/`);
свёртка констант не трогает рантайм-выражения; `fcvtzs/fcvtzu` вне диапазона - UB, как в C.
**libc-lite:** `%f %e %g` (точные, до чётного как glibc) включаются `#define KCC_PRINTF_FLOAT` перед `<stdio.h>` (`kcc/include/kfmt.h`): иначе hello.c в kcc-на-Кире не
укладывается в арену 4 МБ (пик hello.c: было 4 173 040 байт, стало 4 177 712 при выключенном %f; предел 4 194 304).
**Тесты:** `run/r_float_*.c` (арифметика, границы преобразований, NaN/inf, Ньютон, матрицы, вызовы, массивы/структуры, константы, условия: IR-интерпретатор, ELF x86-64
и AArch64 против clang -O0), `exec/x_float_*.c` (printf, variadic, структуры), `ok/float_*.c`, `unsup/long_double*.c`, проверка `-mno-sse`.
**Замеры** (`tests/kcc/bench/fmatmul.c`, double 120x120x40, минимум из 15 запусков, три прогона на тихой машине, kloader против clang -O2): kcc 36.4/36.7/36.6 мс,
clang 27.4/26.8/27.0 мс, отношение 1.33-1.37 (целочисленный matmul в тех же условиях 1.65); код .text 710 против 582 байт. Шум замеров на этой машине +-20%.
Clang -O2 векторизует (mulpd/addpd), kcc - скалярный SSE2 без развёртки.
