# KIRA OS — реестр состояния проекта

Это единая рабочая карта файлов и функций. Она разделяет проект на три постоянных раздела:

Текущая реализация реестра находится в Draft PR [#148](https://github.com/Masuku4129/kira_os_/pull/148); он не объединён в main.

1. **Готово / базовая поставка** — код, уже находящийся в текущем baseline main, и реальные входы штатных сборок. Это не означает, что все функции проверены на физическом оборудовании.
2. **В работе / сохранённые ветки** — изменения в PR и ветках, которые ещё не вошли в baseline. Их файлы не считаются потерянными и не переносятся автоматически.
3. **Запланировано** — требования мастер-плана, для которых ещё нет завершённой production-реализации и доказанного критерия готовности.

## Правило учёта файлов

- Каждый файл текущего дерева обязан находиться в зафиксированном baseline или в managed_files этого реестра.
- Удаление/переименование baseline-файла намеренно блокируется проверкой, пока реестр не будет обновлён после проверки всех consumers, сборок и тестов.
- Новый файл также блокирует проверку, пока его не внесут в одну из трёх категорий и в manifest.
- Файлы, найденные только в других ветках, сохраняются в снимке с точными SHA и именами веток. Они не объявляются включёнными в поставку.
- Нельзя удалять ветки/PR с неинтегрированными файлами по возрасту или названию.
- Перед каждой задачей обновлять live SHA/PR/CI; этот снимок датирован 2026-11-13 и не является динамическим GitHub API.

## Значение статусов

BASELINE = присутствует в основной ветке и учитывается штатной сборкой или репозиторием.
IN_PROGRESS = существует в отдельной ветке/PR, но ещё не принят в baseline.
PLANNED = требование мастер-плана, для которого нет завершённой реализации с доказательствами.
UNVERIFIED = код или сборочный путь обнаружен, но необходимая проверка на указанной среде/точном SHA отсутствует.

**Важно:** наличие файла, успешная компиляция и успешный запуск на реальном устройстве — три разных статуса.
