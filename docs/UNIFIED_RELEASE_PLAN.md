# KIRA OS — единый интегрированный выпуск

**Статус:** план интеграции и критерии готовности; это не объявление релиза.  
**Базовый commit:** `3d09557ef664f7d0f902e3d026baf99505588f86`  
**Исходная ветка:** `v46/iommu-network-compile-fixes`  
**Связанный PR:** #44 — сохраняется открытым и не объединяется автоматически.

## Обязательное правило выпуска

Пользователь получает **один** итоговый выпуск после завершения согласованного первоначального плана и интеграции уже сделанных работ. Промежуточные этапы разработки, ветки, коммиты и CI-артефакты не являются пользовательскими обновлениями и не должны предлагаться как частичные релизы.

Итоговый комплект должен быть собран из одного точного проверенного commit и включать:
- готовый x86-64 ISO, пригодный для проверки в Limbo;
- ARM64 образ/артефакт сборки с честно указанными ограничениями загрузчика и аппаратной проверки;
- комплект обновления с исходниками и необходимыми файлами установки;
- Termux-инструкцию, которая проверяет целевой путь и безопасно устанавливает/заменяет образ в Android Download;
- CHANGELOG, manifest, SHA-256SUMS, скрипт проверки;
- сводный TEST_REPORT с привязкой к SHA, CI run, QEMU и host-тестам;
- отдельный перечень проверок, требующих физического оборудования.

## Сохранённые наработки на исходном commit

Весь существующий код и история сохраняются. В частности, изменения PR #44:
- SMMUv3: подготовка контроллера, проверка ID-регистров и возможностей, выделение/выравнивание stream table и очередей, корректировка регистров и Event Queue, очистка cache, синхронизация команд, освобождение выделений при ошибках;
- VT-d: исправления структуры context entry, общей root table, cache-clean перед публикацией, ограничения 48-bit walk/IOVA и проверки;
- ARM64: исправления FDT include и framebuffer translation units;
- RTL8139: исправление TX error status bits;
- host regression для SMMUv3 prepare и обновление полного PR CI matrix;
- исправления, необходимые для строгой сборки и тестов.

Эти изменения не считаются завершёнными реализациями IOMMU: до безопасного включения DMA нужны полноценные архитектурные домены, корректные STE/CD, map/unmap, invalidation, fault handling, teardown, concurrency и отрицательные тесты. Не включать bus mastering для недоверенных устройств без доказанной изоляции.

## Последовательность внутренней работы

1. **Зафиксировать исходное состояние:** сравнить текущую ветку с base, инвентаризировать реализации и тесты; обновлять HANDOFF/ARCHITECTURE только по фактическому коду.
2. **Завершить GUI:** аудит WM/compositor/input/apps; реализовать отсутствующие системные окна и навигацию; провести геометрические, кириллические, масштабные, ресурсные и многоконные тесты.
3. **Завершить Mind и API:** сохранить существующие модели/формат данных; добавить измеримые task-specific прогнозы только при наличии источников; усилить безопасную политику и rollback; проверить все шесть GUI-разделов на реальных опубликованных данных.
4. **Закрыть системные блокеры:** boot chain, KCC, driver provenance, KDRV trust/anti-rollback, IOMMU/DMA, ACPI/ARM cache maintenance, storage/network.
5. **Сквозная интеграция:** собрать единое ядро, GUI, Mind, драйверы, KiraFS, сеть, приложения и установщик; убрать временные несогласованности и stale docs.
6. **Полная проверка:** x86-64/ARM64 `-Werror`, host tests, compiler tests, driver E2E, GUI/Mind quality, BIOS/UEFI и QEMU matrix, image audit, Limbo install/boot instructions. Не смешивать QEMU с физической аппаратной проверкой.
7. **Единая упаковка:** один commit → полный CI → ISO/KiraFS audit → один архив с ISO, update files, Termux installer, report, manifest и checksums. Gate не обходить и открытые критерии не помечать закрытыми без доказательств.

## Правила статуса

Для каждой функции отдельно указывать:
1. написано и находится в ветке;
2. собрано;
3. host/CI тесты прошли;
4. QEMU сценарии прошли;
5. проверено в Limbo пользователем;
6. проверено на физическом оборудовании.

«100% кода» не является критерием готовности. Критерий — работающая реализация с тестами, безопасными отказами и доказательствами на заявленной платформе.
