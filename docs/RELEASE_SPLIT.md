# KIRA OS v46 — разделение обновления на две части

**Решение владельца проекта (2026-11-08):** единое обновление делится на две части. Это решение продукта, а не снятие требований:
отложенные пункты остаются в `docs/RELEASE_GAPS.md` открытыми и не помечаются закрытыми.

## Часть 1 — сейчас
| Что | Раздел RELEASE_GAPS | Критерий |
|---|---|---|
| Собственный загрузчик (BIOS и UEFI без GRUB в цепочке запуска) | 1 | BIOS-диск из stage1/stage2 грузит production-ядро в QEMU SeaBIOS (маркер ядра по UART); UEFI уже грузит в OVMF; в итоговом ISO/дисковом образе GRUB не нужен для запуска |
| Собственный компилятор KCC | 2 | самосборка x86-64: stage1 == stage2 == stage3 (СДЕЛАНО, `tests/kcc/selfhost.sh`); дальше — расширение охвата, честные границы в документе |
| ИИ («Разум», Mind) | 7 | шесть разделов панели на реальных данных, сохранение и восстановление, лимиты, откат |
| Интерфейс (GUI, композитор wm.c) | 7 | аудит окон, ввода, кириллицы, нехватки памяти; длительные тесты |

## Часть 2 — позже («драйверы»)
Раздел 3 (RTL8139 clean-room), 4 (подписи драйверов, anti-rollback), 5 (изоляция DMA: VT-d, ARM SMMU), 6 (ACPI/ARM платформа).
Уже сделанное в ветке (исправление VT-d IOTLB, проверка подписей, пул DMA) остаётся в коде, но как завершённое не объявляется.
Для драйверов остаётся действовать правило «fail-closed»: недоверенные устройства без доказанной изоляции DMA не получают bus mastering.

## Что это значит для выпуска
- Пакет части 1 помечается как «часть 1 из 2»; в отчёте перечислены отложенные разделы и причина.
- Проверка `ci/release_gate.py` не ослабляется молча: для выпуска части 1 в неё добавляется явный, проверяемый список отложенных разделов, который ссылается на этот документ.
- Физическое оборудование не проверялось; QEMU/OVMF — не доказательство для железа.
