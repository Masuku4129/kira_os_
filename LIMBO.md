# Kira OS в Limbo x86 (Android)

## Сборка в Termux
```
./build_clang.sh --android
```
В Download появятся:
- `kira.iso` - загрузочный образ (GRUB + ядро);
- `kira_disk.img` - диск KiraFS: программы /bin, опыт и модель Разума (/var), файлы программ (/data).

Повторная сборка обновляет `kira_disk.img` на месте: новые программы в /bin, опыт и данные остаются.
Перед сборкой остановите машину в Limbo (образ диска не должен быть открыт эмулятором).

## Настройки машины в Limbo
- Architecture: x64; Machine Type: pc; CPU Model: qemu64 (или max).
- CPU Cores: 1-4 (система сама подстраивается под число ядер); RAM: 512-2048 МБ.
- **Enable MTTCG: включить.** Без галочки Limbo эмулирует все ядра одним потоком телефона: внутри системы ядра есть,
  но работают по очереди, и сборка кадра на всех ядрах не быстрее, чем на одном (стенд: limbo-spam против limbo-mttcg).
  Если в Limbo выключен ACPI, список процессоров берётся из таблиц Intel MP (их даёт BIOS эмулятора); в журнале - строка
  `[KIRA ACPI] Using Intel MP tables`. Если галочка ACPI есть - её можно включить, тогда список берётся из MADT.
- VGA Display: **std** (лучше всего). Если выбран другой адаптер и он не даёт 32-битного режима, ядро работает и в 24/16/15 битах, но медленнее.
- CD-ROM: `kira.iso`; Hard Disk A: `kira_disk.img`; Boot from: CD-ROM.
- Интерфейс диска: IDE (по умолчанию) - ядро использует драйвер ATA; если в Limbo есть virtio для диска - тоже работает (virtio-blk, быстрее).
- Mouse: **usb-tablet** - лучший вариант для сенсорного экрана: касание ставит курсор в точку касания (абсолютные координаты).
  Работает и PS/2 (режим трекпада, относительная мышь), и usb-mouse. USB-клавиатура (usb-kbd) тоже поддерживается.
  Контроллер USB в Limbo - UHCI (-usb); если в настройках есть xHCI (qemu-xhci) - тоже работает.
  Команда `usb` в терминале показывает контроллеры и найденные устройства: `планшет` - касание ставит курсор в точку;
  `мышь` - относительная мышь: с сенсорным экраном курсор расходится с пальцем (так у любой ОС), это режим для DeX и
  настоящей мыши. Там же - как разобран отчёт устройства и последний отчёт (если что-то работает не так - пришлите этот вывод).
- UI: SDL - картинка без сжатия VNC.
- Network: **User**, сетевая карта (NIC): **e1000**. Система сама получает адрес по DHCP; команды `net` (состояние)
  и `ping 10.0.2.2` (шлюз Limbo). Sound: **hda** - команды `sound` и `beep 440 500`.

## Режим экрана
В меню GRUB (4 секунды):
- `1280x720` - по умолчанию;
- `1920x1080` - для внешнего монитора, самая чёткая картинка (больше точек - эмулятору тяжелее);
- `1600x900`;
- `1024x768` - для медленного эмулятора;
- `1280x720 + x2APIC` - для современных ПК.

Если адаптер не умеет выбранный режим, GRUB берёт следующий из списка в пункте меню.

## Что важно знать
- Limbo, как и QEMU в Termux, эмулирует процессор программно (без KVM): быстрее он не станет; выигрыш - в чёткости
  (SDL без сжатия, родное разрешение) и в том, что не нужен proot.
- Журнал ядра идёт и в последовательный порт; в Limbo его можно не смотреть - всё видно в Терминале оболочки.

## Флешки и USB-хабы (v26)

- Флешки FAT12/16/32 подключаются ТОЛЬКО ДЛЯ ЧТЕНИЯ; запись разрешает человек командой `remount usb0 rw` (обратно: `remount usb0 ro`). Система читает и пишет флешки FAT12/16/32 (exFAT и NTFS - пока нет: отформатируйте в FAT32). Флешка появляется
  в проводнике и в терминале как `/usb0` (до четырёх: `/usb0`..`/usb3`). Перед извлечением: `umount usb0`.
- Команды: `df` - тома и свободное место, `ls /usb0`, `cat /usb0/файл.txt`, `cp /usb0/файл /data/файл`, `usb` - дерево
  устройств (порт `3.2` - порт 2 хаба на корневом порту 3).
- В QEMU (Termux): `./build_clang.sh --vnc --xhci --hub --flash` - хаб, клавиатура, планшет и флешка `kira_flash.img`
  (создаётся сама, нужен `apt install dosfstools mtools`). Своя флешка: `--flash=путь.img`.
- В Limbo флешку можно подключить, только если в вашей версии есть поле дополнительных параметров QEMU
  (Extra Params): `-drive if=none,id=stick,format=raw,file=/storage/emulated/0/Download/kira_flash.img -device usb-storage,drive=stick`.
  Меню Limbo такого устройства не предлагает - это ограничение эмулятора, не системы.
