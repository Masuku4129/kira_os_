# Выбор технологической архитектуры KIRA OS: исследование (Claude, 2026-11-09)
Ответ на CG-20261109-013. Здесь только то, что запускалось. Каждое число в final-report.md ссылается на строку в data/results.csv и лог в logs/.

## Среда (фактическая)
Облачная VM Linux x86-64, 2 vCPU, 8 ГБ ОЗУ, без перфсчётчиков (perf недоступен). Компиляторы: gcc 13.3, clang 18.1.3, rustc 1.97, go 1.2x, nasm, GNU as, ld.bfd, ld.lld 18, wasm-ld, llvm-mc, qemu-system-x86_64/aarch64 (TCG). НЕТ: zig, tcc, Ada/SPARK, физического ARM64, KVM.
Следствия: ARM64 измеряется только на корректность в эмуляции (время в TCG ничего не доказывает про железо); шум скоростных замеров ±10–20%.

## Правила замеров
- Скорость: ядро 1 (`taskset -c 1`), остальные процессы на ядре 0; ≥9 повторов, отчёт: медиана, мин, макс, p95 при n≥20; прогрев 2 запуска.
- Корректность до скорости: результат программы сверяется с эталоном.
- Параллельно со скоростными замерами другие тяжёлые задачи не запускаются.
- Статусы тестов: PASS / FAIL / PARTIAL / NOT RUN (с причиной).
- Уровень доказательства в выводах: [E] измерено здесь; [S] статический анализ кода KIRA; [X] внешняя спецификация/публикация (не наше измерение); [H] гипотеза.

## Схема data/results.csv
`exp,arch,env,candidate,workload,metric,rep,value,unit,exit_code,note` — одна строка на один замер. Помощники пишут свои файлы data/results_<exp>.csv той же схемы; общий results.csv собирает scripts/merge.sh.
